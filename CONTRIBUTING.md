# Contributing

Thanks for helping improve this guide.

## How to suggest changes

1. Fork this repository.
2. Create a branch for your change.
3. Keep edits focused and practical.
4. Open a pull request with:
   - what changed
   - why it helps
   - any tradeoffs

## Scope for this repo

- Keep guidance generic across macOS, Linux, and Windows.
- Prefer beginner-friendly language.
- Keep safety and reproducibility first.
- Avoid adding vendor-specific lock-in unless clearly marked optional.

## Writing style

- Use plain language.
- Prefer short sections and checklists.
- Explain decisions with practical constraints.

## Security

Do not commit real secrets, tokens, or live `.env` files.
